# M08 Prior Art：实际缺口与复用边界

日期：2026-09-14。用途：支持计划，不代表实现或运行验证。目标为 API 17、Java/OkHttp 3.12.13 的有界上下文与可取消 SSE；不寻找替代整个 SmartTube/翻译系统。

## 仓库现实与缺口

| 能力 | 状态 | 本地证据 |
|---|---|---|
| session/generation/epoch | EXISTING | ai/subtitle/session 与 scheduler |
| 草稿/final 模型与回调 | EXISTING | translation/TranslationResult、TranslationStream |
| context 缓存字段 | PARTIAL | TranslationCacheKey 有字段；Scheduler 固定空字符串 |
| Prompt context 变量 | PARTIAL | PromptVariable.CONTEXT 存在，生产 Adapter 仍硬编码 systemPrompt |
| 增量 HTTP 读取 | MISSING | OkHttpRequestExecutor 使用 body.string() |
| SSE 分帧/两协议解释 | MISSING | 两 Adapter 普通响应；OpenAI stream=false |
| 内存缓存 | EXISTING，但未设容量 | InMemoryTranslationCache 使用 HashMap |
| 磁盘翻译缓存/摘要 | MISSING，路线图可选 | 不先建数据库或摘要服务 |

## 检索范围与候选

已检查本地 Provider/http、translation、cache、Prompt、依赖声明、architecture/roadmap；外部读取标准与官方实现。不是对整个生态做穷尽搜索：缺口很窄，宿主已有 transport 与身份模型。

| 候选 | 分类 | 结论 |
|---|---|---|
| 当前 OkHttpRequestExecutor + Okio | REUSE/ADAPT | 继续拥有 HTTP/取消/错误归一化，补流读取 |
| Square okhttp-sse 3.12.13 | REFERENCE，未直接引入 | 同版本实现值得参考；缺少本任务需要的缓冲上限；需要额外依赖与总超时语义处理 |
| WHATWG SSE wire format | REFERENCE → 独立小分帧器 | 明确 UTF-8/换行/事件边界，不做浏览器 EventSource 自动重连 |
| 完整 OpenAI/Anthropic SDK | 不采用 | 仓库已有两协议、五 Provider、密钥与取消；引入 SDK 重叠过多，未证明 API 17 兼容，未做其全量源码审计 |
| 新通用 agent/context 框架 | 不采用 | 所需只是标题+描述+最近三个单元预算，当前串行调度足够 |
| KissTranslator 浏览器 SSE/context | 仅行为参考 | GPL/浏览器专用边界，不能复制进入 MIT 宿主 |
| Android 平台数据库 | 本轮不采用 | 无重复请求成本证据，不预设计 schema/TTL/迁移；实际需要时再调查 |

## 关键已读证据与限制

- 本地 `SharedModules/constants.gradle:84` 固定 okhttpVersion=3.12.13；本轮不升级它。
- [Square RealEventSource 3.12.13](https://raw.githubusercontent.com/square/okhttp/parent-3.12.13/okhttp-sse/src/main/java/okhttp3/internal/sse/RealEventSource.java)：使用响应源增量处理、取消底层 Call、不自动重试，代码也清除了 call timeout。直接采用须另补总期限和输入预算；不能以“官方已有”假定满足本项目边界。
- 同版本 ServerSentEventReader 源页多次读取失败，未声称逐行审计该文件。即使后续采用库，也应先完成大小上限/取消/超时 spike。
- [WHATWG SSE](https://html.spec.whatwg.org/multipage/server-sent-events.html)：作为分帧规则依据。
- [OpenAI Chat Completions 流事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)：本项目使用 Chat Completions，不能拿 Responses 事件名直接套用。
- [Anthropic streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)：具名事件、文本 delta 与结束事件，协议解释留在 Adapter。

## 决策

选 **复用当前 HTTP/session/cache/Prompt/回调模型 + 独立有界 SSE 分帧器**。不复制 Square/GPL 源码。新代码的必要性是同时满足既有 executor 边界、API 17、严格字节上限、统一重试预算和总期限，而不是新建整个网络栈。

context 使用标准集合拼接字符串并交给现有 PromptRenderer；直接对最终 renderedPrompt 做 SHA-256，填既有缓存指纹字段，不新建 Snapshot/编码协议。无外部 tokenizer，字符/字节上限不冒充精确 token 预算；沿用单并发与当前 unit 优先。

Ponytail 复查后，持久缓存/摘要默认不实施：在 M08 报告记录缺少收益证据和触发条件即可，不把可选实验设成 M09 前置门槛。实际发现重复请求成本或上下文质量问题后再测量；届时才设计存储/摘要能力。未运行的实验与兼容性检查不能写成通过。

## 上游影响

新增/修改限 AI feature package、测试、三套资源和文档。无新宿主 hook，无 SharedModules/MediaServiceCore 修改，无构建依赖升级。M09 对实际 upstream diff 再核实。
