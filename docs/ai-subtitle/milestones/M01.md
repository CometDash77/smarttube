## Findings that changed the initial plan

1. SmartTube already has a complete native YouTube caption pipeline and YouTube `tlang` support. KissTranslator caption discovery is discarded.
2. `PlaybackPresenter` is a strong controller lifecycle seam; only one registration hook is expected.
3. `SubtitleManager` already centralizes all rendered cues, so a one-cue decorator is preferable to a second overlay or renderer fork.
4. Lookahead requires a full-track source, but the currently selected Exo format does not reveal a stable timed-text URL. An adapter-first spike precedes any loader hook.
5. Provider brands collapse into two protocol families in current official documentation.
6. KissTranslator's GPL license makes clean-room behavior/test extraction the default migration mechanism.
7. Existing GitHub Actions builds/lints only `master` or manual dispatch and does not explicitly run unit tests; a feature-owned CI lane must precede implementation acceptance.
8. The personal project `origin` is the project system of record; official SmartTube is a separate `upstream` remote.
