## REQUIRED OUTPUT INTERFACES

Use these stable M02 interfaces. Do not introduce Provider brands, prompts, HTTP, full-track parsing, persistent translation cache, or segmentation types yet.

```java
public interface TranslationProvider {
    TranslationCall translate(TranslationRequest request, TranslationCallback callback);
}

public interface TranslationCall {
    void cancel();
    boolean isCancelled();
}

public interface TranslationCallback {
    void onSuccess(TranslationResult result);
    void onFailure(Throwable error);
}
```

`TranslationRequest` is an immutable value object with:

```text
long generation
long requestId
String sourceText
String sourceLanguage
String targetLanguage
```

`TranslationResult` is an immutable value object with:

```text
long generation
long requestId
String translatedText
```

`FakeTranslationProvider` returns `[ZH] ` plus the exact source text and never touches the network. It must honor `TranslationCall.cancel()` and return failure for null/blank source rather than fabricating content.

`AiSubtitleData` exposes:

```java
public static AiSubtitleData instance(Context context);
public boolean isEnabled();
public void setEnabled(boolean enabled);
```

It uses a dedicated named preference store, defaults to false, and stores no Provider/Profile data in M02.

`AiSubtitleCueBridge` exposes one renderer-facing method:

```java
public List<Cue> process(List<Cue> processedSourceCues);
```

It also exposes lifecycle methods used only by `AiSubtitleController`:

```text
onNewVideo(String videoId)
onSubtitleTrackChanged(String trackIdentity)
onSeek(long positionMs)
onPause()
onPlay()
onRelease()
```

The exact Java visibility may be reduced where tests and integration permit, but the renderer must know only `process`, and the controller must not know `SubtitleView`.

## BEHAVIOR REQUIREMENTS

### Cue bridge

1. When the setting is disabled, null, empty, and non-empty cue lists preserve current SmartTube behavior.
2. Run AI processing only after `forceCenterAlignment`; do not bypass SmartTube's existing ASR cleanup.
3. Preserve the source text exactly as received from the processed Cue.
4. Render one Cue whose text is `source + "\n" + translation` when a valid translation exists.
5. While a result is missing, late, cancelled, invalid, or failed, return the source cue unchanged.
6. Do not put `[Translation failed]`, ellipses, exceptions, or status text into captions.
7. Never make a network call or block the renderer thread.
8. Deduplicate an in-flight fake request for the same generation and source text.
9. Apply a callback only when both generation and request ID still belong to the active request.
10. Catch feature exceptions at the bridge boundary and preserve source-only output.

For M02 only, normalized source text may be the in-memory lookup key. This limitation must be documented in the Worker Report; M03 replaces it with timeline/segment identity before real providers are allowed.

### Lifecycle controller

1. Register one `AiSubtitleController` immediately after `VideoLoaderController` in `PlaybackPresenter`.
2. New video, subtitle track change, subtitle disable/off, engine release, and finish cancel outstanding calls, increment generation, and clear prior translation state.
3. Seek cancels obsolete in-flight work and advances a scheduling epoch/generation guard; no old callback may repaint the current session.
4. Pause prevents admission of new fake work; resume permits it again.
5. Repeated lifecycle events are idempotent and cannot throw into `PlaybackPresenter`.
6. Non-subtitle track changes are ignored. Use `PlayerEngineEventListener.RENDERER_INDEX_SUBTITLE`/the existing `FormatItem` metadata rather than language-name guesses.

### Settings

1. Add one switch at the start of the existing subtitle settings dialog after the native subtitle-channel option.
2. Label it with a new resource in `ai_subtitle_strings.xml`: `AI bilingual subtitles (test provider)`.
3. Default false.
4. Switching off immediately cancels/clears AI state and restores source-only captions on the next cue update.
5. Do not add Provider, Model, Prompt, API key, target-language, style, or advanced settings in M02.

### Rendering

1. Use the existing `SubtitleView`; do not add views or layouts.
2. Use one combined Cue; do not create a second overlay.
3. Both lines may use the current SmartTube subtitle style in M02. Separate line styling is not required in this baseline.
4. Do not enable embedded styles or change `SubtitlePainter` merely for the `[ZH]` baseline.

## STATE / INVARIANTS

- Source captions and player playback are always authoritative.
- Default-off behavior must be equivalent to upstream behavior.
- Generation is monotonically increasing for invalidating events.
- No result from an older generation may mutate current bridge state.
- The bridge owns no Activity, View, SubtitleView, Video, or PlaybackPresenter reference.
- The controller owns no Cue or Provider serialization logic.
- The fake provider owns no player or settings reference.
- All outstanding calls are cancelled on release.
- M02 contains no network permission change, endpoint, API key, or Provider brand.

## EDGE CASES

- null cue list;
- empty cue list;
- Cue with null or blank text;
- source text already containing a newline;
- duplicate visible source text;
- provider callback after video change;
- callback after track change;
- callback after seek;
- callback after disable;
- repeated pause/resume;
- repeated release/finish;
- subtitle track disabled and re-enabled;
- non-subtitle audio/video track change;
- bridge/provider exception;
- two rapid calls for the same source cue;
- app/player reopen with setting enabled and with setting disabled.
