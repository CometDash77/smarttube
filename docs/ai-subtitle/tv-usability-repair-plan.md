# AI 字幕：电视实测问题检查与修补计划

日期：2026-09-13
检查基线：r5（`6ddf9cad2`）及用户的 8 项实测反馈。
本文是待执行计划；代码检查结果不等于真机验收通过。

## 目标与实施原则

用户应能在电视上完成这条路径：安装 → 选择服务商 → 用手机输入 → 得到明确的测试结果 → 播放时开启 AI → 看见翻译进度与译文 → 随时切换双语或仅译文。

按 Ponytail full 执行：复用现有 ProviderPreset、配置存储、SecretStore、翻译适配器、字幕会话和播放器菜单；只补缺失的交互及数据通知。不另建配置体系、翻译引擎、网页应用框架或通用远程控制平台。手机输入是本次明确需求，必须实现，不能以“简化”为由省略。

## 二、执行顺序与验收

### 阶段 A：安装诊断与真正显示译文（P0）

#### A1. 架构 APK 安装问题（反馈 1）

检查步骤：

1. 获取设备型号、Android 版本、系统支持的 ABI 列表，以及实际失败 APK 的名称。64 位 CPU 不代表设备运行的是 64 位 Android。
2. 下载同一 Release 的四个 APK，逐个比较发布哈希、签名证书、Manifest、最低系统版本、ABI 和 `lib/<abi>` 内容。
3. 在受影响设备上安装与 ABI 匹配的包，获取系统安装错误及日志；区分 ABI 不匹配、缺少 native 库、包损坏、系统版本不兼容、已有应用签名冲突等原因。
4. 比对 universal 与匹配架构包；重点核查 `ndk.abiFilters` 与 `splits.abi` 的最终产物，不能仅依据文件名判断架构。
5. 确认根因后修改打包或分发说明，不随意降低 SDK 或关闭校验。

验收条件：

- universal 在用户设备安装并启动成功。
- 用户设备对应的架构包也安装并启动成功；不要求同一设备安装所有互不兼容的 ABI 包。
- 每个公开架构包都有匹配环境的安装与启动记录；模拟器测试明确标注，不能代替受影响真机复测。
- 尚未完成匹配环境验收的架构包不标为“已验证可安装”；测试发布以已验证的 universal 为推荐下载。
- 覆盖安装保留设置；发现签名冲突时明确说明，不把卸载旧版作为默认排障步骤。

#### A2. 修复异步译文刷新（反馈 6、7 的底层前提）

- 复现：固定显示一条足够长的字幕，让翻译延迟返回；期间不触发新的 `onCues`，检查译文是否出现。
- 复用现有会话、请求标识和缓存。接受结果后，只通知仍属于当前视频、字幕轨、播放位置和活动字幕的 UI 刷新。
- 在主线程重绘保存的当前原文 cues；重绘不能重复断句、再次污染原文缓冲或重复发起请求。
- 生命周期注册和移除通知，避免桥接单例持有已经销毁的播放器视图。
- 开关或显示模式切换也应刷新当前字幕，不等下一句才生效。
- 已过期的译文不得突然覆盖当前字幕；多次失败不能形成每次重绘都重试的请求循环。

验收条件：

- 异步译文在当前字幕仍有效时直接出现，不需要暂停、拖动或重复播放。
- 快进、换视频、换字幕轨、退出播放后，旧请求不会回写到新画面。
- 网络失败不阻断原字幕和视频；保留一项能捕获“成功入缓存但没有重绘”的回归测试。

### 阶段 B：服务商配置、中文与明确反馈（P0/P1）

#### B1. 官方默认地址与 Custom（反馈 8）

- 选择 OpenAI、Anthropic、DeepSeek 等已有预设时，直接使用 ProviderPreset 的地址和协议，自动生成配置名称；普通流程只需密钥、模型和目标语言。
- 官方预设的 URL 作为只读信息展示，不要求用户填写。自建网关、代理地址统一进入 Custom。
- Custom 提供 Base URL 和协议选择；复用已有 OpenAI Chat Completions / Anthropic Messages 适配器，不靠地址字符串猜协议。
- 模型优先从可用列表选择，保留手动填写；列表读取失败不能被误判成模型一定不能翻译。
- 编辑已保存配置时不覆盖用户原有地址；旧配置使用非官方地址的，保留内容并迁移为 Custom。
- 实施时核对服务商官方文档中的地址、路径和鉴权要求；测试避免重复拼接 `/v1` 或请求路径。

验收：新建三个官方服务商配置均无需手填 URL；Custom 地址与协议可保存、编辑并正确请求；旧配置和密钥不丢失。

#### B2. 测试连接必须有结果（反馈 5）

- 点击后立即显示“正在测试”，禁用重复提交，保留取消按钮。
- 使用选中的模型、协议和密钥执行一个最小真实翻译请求；模型发现作为独立辅助步骤，不以 `/models` 成功替代翻译成功。
- 结果页保持到用户关闭：成功显示服务商、模型、耗时和测试译文；失败显示明确的中文原因与下一步。
- 区分缺少密钥、鉴权失败、模型不可用、限流/额度问题、地址错误、网络或 TLS 错误、超时、空响应和无效输出；按已知响应分类，不臆测错误原因。
- 全部界面回调切回主线程；取消、退出和超时都有终态，迟到结果不重新弹窗。
- 不在日志、提示或诊断信息中输出密钥。测试按钮说明会发送一次小额模型请求。

验收：有效配置、错误密钥、错误模型、错误 URL、断网、超时及取消，每一种都有可看见的结果；“无反馈”和无限等待均判失败。

#### B3. 中文与电视可读性（反馈 3）

- 使用现有 `values-zh`、`values-zh-rTW`，补齐简繁中文 AI 文案；保留默认英文资源。
- 范围包括模式、配置、模型、目标语言名称、Prompt 操作、测试结果、错误、播放状态、手机配对和输入页面。
- 品牌名与模型 ID 保留原名；面向用户不只显示 `zh`、`en` 等代码。
- 校验遥控器焦点、返回路径、长文案换行和电视距离下的可读性。

验收：中文系统下完整走完配置、测试、播放及手机输入，所有操作性文案均为中文，无截断和焦点死角。

### 阶段 C：播放入口、三种模式与真实状态（P1）

#### C1. 播放中能找到 AI（反馈 2、6）

- 控制栏新增清晰的“AI 字幕”文字入口，复用现有动作/菜单机制；现有字幕菜单也可进入同一面板。
- 面板提供“原文 / 双语 / 仅译文”、目标语言、当前服务商与模型、运行状态，以及配置入口。
- 设置页和播放页读写同一个模式值。旧 AI 关闭迁移为“原文”，旧 AI 开启迁移为“双语”。SmartTube 原有“字幕关闭”仍独立有效。
- “仅译文”成功时只显示译文。建议的失败策略：尚未取得译文或翻译失败时暂时显示原文，并明确标记“等待译文”或“已回退原文”，避免无提示黑屏；该规则要在模式说明里写清楚。
- 未配置服务商时，开启操作引导到配置；没有可用字幕轨时显示原因。AI 字幕翻译不等同于无字幕视频的语音识别。

验收：用户在视频中可直接找到入口并切换三种模式；当前句及时更新，重启后保持选择，字幕总开关仍正常。

#### C2. 状态必须由真实事件驱动（反馈 7）

用少量明确状态覆盖用户真正需要知道的情况：

| 状态 | 触发依据 | 用户看到的内容 |
|---|---|---|
| 已关闭 | AI 模式为原文 | AI 已关闭 |
| 待配置 | 缺少有效配置 | 尚未配置服务商，进入设置 |
| 无字幕 / 等待字幕 | 没有字幕轨 / 有轨但尚无文字 | 当前视频无字幕，或正在等待字幕 |
| 正在翻译 | 已提交当前有效请求 | 正在翻译，可查看当前模型与耗时 |
| 已显示译文 | 当前有效译文实际交给渲染器 | AI 译文已显示；需要时注明缓存命中 |
| 失败并回退 | 请求失败或超时 | 原因、已回退原文、重试入口 |

- 不能仅因用户打开开关就显示“翻译中”，也不能因接口返回成功就显示“译文已显示”。
- 控制栏关闭时不逐句弹通知；启用、首次译文和故障可简短提示，持续详情保留在 AI 面板。
- 保留当前会话的轻量诊断：是否收到字幕、请求是否发出、耗时、成功/失败数、最近错误；不另建监控平台。

验收：新用户不看日志，也能判断是否启用、是否请求、是否显示，以及失败在哪里。

### 阶段 D：局域网手机实时输入（P1，反馈 4）

交互顺序：

1. 电视在输入阶段提供“用手机输入”。选择后启动短期局域网服务，显示二维码和可手输的网址。
2. 手机与电视处于可互访的同一局域网，扫码打开页面。服务必须在二维码显示前启动，否则扫码没有页面可访问。
3. 手机展示配置表单：服务商、模型、目标语言、密钥，Custom 的地址与协议，以及需要编辑的 Prompt。
4. 手机键入、删除、粘贴和修改后，同步到电视的编辑草稿；手机和电视都显示连接及保存状态。中文输入法组词过程中不提交半成品。
5. 点击“保存并测试”后复用同一套校验和配置存储，两端显示测试结果；无效半成品不得替换正在使用的配置。
6. 完成、取消、退出配对页或会话超时后关闭服务，旧链接失效；断线可提示重连或重新生成二维码。

最小实现方案：

- 一张静态手机页面和少量限定用途接口即可，采用短延时合并提交；双向同步优先短轮询，只有测量证明体验不达标才增加 WebSocket。
- 不添加 React、账号登录、云中转或常驻后台服务。先检查整个依赖树；没有可复用的 HTTP 服务时选兼容项目最低 Android 版本的轻量组件，不手写通用 HTTP 解析器。
- 草稿带版本，明确手机/电视同时编辑时的冲突处理，迟到请求不得覆盖新内容。成功同步目标为正常局域网下约 1 秒内可见。
- 用户主动开启会话，使用短期随机配对凭证；接口校验会话、来源、Host、请求大小和可编辑字段，不暴露文件系统或任意命令。
- 二维码在本地生成。现有 `Utils.toQrCodeLink` 使用第三方在线二维码服务，不适合发送含配对凭证的局域网链接。
- 密钥不放 URL、不写页面日志或浏览器持久存储；现有密钥只显示“已设置”，允许替换/清除，不回传明文。
- 识别无局域网地址、访客网络隔离、Wi-Fi/网线双网络和网络切换，显示可操作的提示；保留遥控器输入作为备用方式。

验收：手机无须安装应用即可扫码；断开互联网但保留局域网时仍能编辑；增删改、长文本、多行 Prompt、中文输入及密钥替换正确；断线、过期和退出后有明确反馈；未配对请求无法修改配置。

## 四、发布完成的条件

- [ ] 8 项反馈逐项留下“通过 / 未通过 / 待设备确认”的记录，没有以编译成功代替验收。
- [ ] 安装：用户设备上的 universal 和匹配架构包通过安装、启动；未验证的架构不声称兼容。
- [ ] 配置：三个官方预设免填 URL，Custom 可编辑，中文完整，手机可实时增删改。
- [ ] 测试：每种成功或失败都有可保留的可见结果，无无限等待。
- [ ] 播放：入口可见，三种模式有效，异步译文实际出现，状态与真实请求和渲染一致。
- [ ] 生命周期：快进、暂停、换视频、换轨、退出和关闭 AI 没有旧译文残留。
- [ ] 必要回归检查通过：异步刷新与过期结果、模式迁移、测试终态、手机会话失效与草稿同步。
- [ ] CI、公开下载、哈希及签名校验通过；升级包继续使用已有测试签名密钥，并提供可识别的构建版本。
- [ ] Release 附有本轮用户路径验收结果、适用架构和已知限制，交付已验证下载链接。

建议交付节奏：先完成 A，再完成 B 与 C，最后接入 D 并整体回归。可以阶段性提供内部测试包，但最终修补版必须包含手机输入及全部 8 项验收，不能以其中一批完成代替整体完成。

## 五、执行时需补齐的最少设备信息

安装诊断需要：设备型号、Android 版本、失败包的准确文件名，以及可获取时的系统 ABI / 安装错误。缺少这些信息只影响特定设备的安装结论，其余界面、状态、配置和手机输入修补可以继续推进。
